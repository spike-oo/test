第 8 组 · 指导教师：吴贞东 · 对应需求文档《智能AI校园外卖平台需求分析文档 v3》图 2-1 与第 8 章

一、系统总体架构（四层）

前端展示层
学生端 /student 商户端 /merchant 骑手端 /rider 管理员端 /admin
业务服务层
用户 / 店铺 菜品 / 订单 骑手 / 配送 评价 / 客服 饮食分析
AI 能力层
语义理解 智能推荐 智能客服 评价分析 经营分析
数据存储层
MySQL 业务数据（35 张表） Redis 缓存 / 分布式锁 对象存储（图片） 日志与审计
技术基线：Spring Boot 3.2 + MyBatis-Plus + MySQL + Redis + WebSocket（后端），Vue 3 + Vite + TypeScript + Element Plus（前端），大模型走 OpenAI 兼容 HTTP 接口。

二、四人分工与模块归属

成员端业务范围 后端包（modules/）前端目录数据责任域
成员1 学生端 首页浏览、语义搜索、AI 点餐、购物车、个人中心与饮食画像 user（画像/地址）、cart、ai（点餐 / 搜索 / 推荐 / 饮食分析） views/student 用户与画像域（主责）
成员2 商户端 店铺菜品、库存、订单处理、评价管理、AI 经营辅助 shop、dish、review、ai（评价分析 / 经营分析） views/merchant 商品与经营域（主责）
成员3 管理员端 商户/骑手审核、数据看板、系统配置、知识库、客服工单 admin、ai（智能客服 / 知识库） views/admin AI 与运营域（主责）
成员4 骑手端 + 平台基础 登录鉴权、订单状态机、Redis、WebSocket、骑手抢单与配送 security、order、delivery、websocket views/rider 交易与配送域（主责）
说明：需求文档第 8 章以「成员1—成员4」编号给出分工，姓名待组内确认后替换。

三、订单状态机（全系统唯一改状态入口）

0 待接单→ 1 备餐中→ 2 待取餐→ 3 配送中→ 4 已完成
5 已取消 （0 待接单 / 2 待取餐 可转入，需回补库存并退款）
6 申诉中 （由客服工单触发）
约束：状态只能经 OrderStateMachine.transit() 变更；各端禁止直接 UPDATE；配 @Version 乐观锁 + order_status_log 追加日志；抢单只绑定 rider_id 不改变状态。
