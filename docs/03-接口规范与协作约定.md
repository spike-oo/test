# 03 接口规范与协作约定

## 一、通用约定

| 项目 | 约定 |
| --- | --- |
| 基础路径 | `/api` |
| 版本 | 暂不区分版本；破坏性变更在本文「变更记录」登记 |
| 数据格式 | 请求与响应均为 JSON（文件上传用 `multipart/form-data`） |
| 字符编码 | UTF-8 |
| 鉴权 | 请求头 `Authorization: Bearer <token>` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（`application.yml` 已统一配置） |
| 分页参数 | `pageNum`（从 1 开始）、`pageSize`（默认 10，最大 100） |

## 二、统一响应体

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

分页数据：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 128,
    "pageNum": 1,
    "pageSize": 10,
    "list": []
  }
}
```

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 200 | 成功 | 取 `data` |
| 400 | 参数错误 | 提示 `message` |
| 401 | 未登录 / Token 失效 | 清除登录态，跳登录页 |
| 403 | 无权限 | 提示无权限，不跳转 |
| 500 | 业务异常 / 系统异常 | 提示 `message` |

## 四、WebSocket 约定

| 项目 | 约定 |
| --- | --- |
| 端点 | `/ws/order?token=<jwt>` |
| 消息体 | `{ "type": "ORDER_STATUS", "data": { "orderId": "", "status": 1 } }` |
| 推送对象 | 学生（自己的订单）、商户（本店订单）、骑手（大厅新单） |
| 兜底策略 | 关键状态变更采用「WebSocket 推送 + 前端轮询」双通道，保证消息必达 |
